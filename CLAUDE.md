## How this repo is deployed
- Built in Lovable; this GitHub repo is two-way synced with the Lovable project on the default branch.
- Workflow: edit → `bun run build` passes → commit → push to the default branch → the change appears in Lovable → Hany clicks **Publish → Update** in Lovable to put it live.
- Never force-push or rewrite history (it breaks the Lovable sync).

## Stack (do not migrate)
React + TypeScript + TanStack Start + Tailwind, existing animation library, Lovable Cloud (Supabase) backend. Keep the existing structure; reuse existing code.
- Package manager: **Bun** (`bun.lock`). Use `bun install`, `bun run dev`, `bun run build`. Never commit a `package-lock.json`.
- Also read `AGENTS.md` (architecture rules: screens are pure functions of screen/phase/choice; per-screen `timeline` arrays in `src/content/screens.ts` drive the auto-play; themes in `src/deck/theme.ts`; config in `src/config.ts`).
- Never edit `vite.config.ts` plugins (the Lovable config already includes them).
- Checks before pushing: `bun run build`, `./node_modules/.bin/tsc --noEmit -p .`, `./node_modules/.bin/vitest run` (`src/deck/store.test.ts` asserts slide count, separator positions, Q&A index, 41:30 / 2:00 totals, build-time limits and that slides and sources point at each other — update it when the deck changes). Dev server: `bun run dev` → http://localhost:8080.
- Windows checkout noise: ESLint's prettier rule reports CRLF line endings (ignore, or lint with `--rule 'prettier/prettier: off'`); `src/routeTree.gen.ts` shows as modified after every build (line endings only — `git checkout` it, don't commit). Don't run prettier over whole files: it reflows the one-line-per-slide table in `screens.ts` and unrelated lines.

## Hard rules
- **No third-party services** (no Browserless, no external PDF/render APIs). PDF = `/print` route → Playwright locally → versioned file bundled with the release.
- **Never commit secrets.** The presenter PIN (6–8 digits) is checked by `checkPin` in `src/lib/print-token.server.ts` against the server secrets `PRESENTER_PIN_HASH` + `PRESENTER_PIN_SALT` (PBKDF2, set in Lovable Cloud → Secrets; made with `node scripts/hash-pin.mjs`); TEMPORARY: while the secrets are missing, the old 4-digit PIN (`LEGACY_PIN`, public hash) still works — remove it once the secrets are set. Never put a new PIN, its hash or salt in the repo (the old 4-digit PIN is public — compromised). The `PRESENTER_PIN` secret is no longer used. `.env` values from Lovable (Supabase URL / publishable key) are public client keys; don't add others.
- **Database:** polls use the old `poll_votes` table with added `poll_id` and `option` columns. Do NOT drop/alter the old columns or the `poll_sessions` table. Poll id: `s2-challenge` ("Who's in the room?", 4 options, votes stored in the bucket — see README). `s7-interview` (old slide 12 "Two graduates") is retired; its old `poll_votes` rows stay untouched. Schema migrations only apply via Lovable, so poll open/closed state (`state/polls.json`) and feedback (`feedback/<device>.json`) live in the private `exports` bucket, written by server functions (`src/lib/poll-state.functions.ts`, `feedback.functions.ts`, `store.server.ts`). Routes: `/vote`, `/feedback`, `/results` (PIN, noindex, unlinked), `/thanks` (audience hub, see below). See README "Live polls, feedback and results".
- **Time gate:** until `DECK_UNLOCK_AT` (src/config.ts, 21:00 Cairo) only slides 0–1, `/vote`, `/feedback`, `/thanks` are public (on `/thanks` the deck and PDF cards show "Opens at 21:00 Cairo" + countdown); everything else shows `LockScreen` unless the browser holds a PIN unlock token (6 h, localStorage). Server-checked via `deckGate` / `exportPdf` (`src/lib/deck-gate.server.ts`); client side in `src/deck/gate.tsx`. See README "Time gate".
- **Do not change any slide wording** unless a task says so. All text, quotes and numbers are verified; every number/quote keeps its on-slide SourceTag and its `sources.ts` entry (exact article URLs, never homepages).
- No pure black anywhere.

## How slides are wired
- `src/content/screens.ts` is the single list: one row per slide. **`id` is always `"S" + index`** (S0–S51); renumber every later id when inserting a slide. Row fields: `act`, `title` (control bar / page title / overview), `durationSec`, `steps` + `timeline` (ms per build phase), `notes` (presenter; `**bold**` = key line), `sourceIds`. Separators are made with `sep(id, actNumber, act)` (`separator` field, 1–7 = stop 01–07).
- Components: `S<n>` functions in `src/components/screens/{opening,act1,act2,act3,act5,stops}.tsx`, registered in the `REGISTRY` of `src/components/deck/ScreenRenderer.tsx`. `stops.tsx` holds the agenda (S3), the quote slides (S9, S40), the students myth slide (S21), the skill-shift slide (S28), the `StopPlan` "Your move" slides and the Stop 07 slide (S47). Separator slides all render `ActSeparator` (`screens/separators.tsx`) with text from `src/content/separators.json` and the 7-stop roadmap from `agenda.json`. All slide text lives in `src/content/*.json` (new-stop text in `stops.json`; the Blueprint's full per-role plans in `plans.json`).
- Sources: `src/content/sources.ts` entries list the slide ids they belong to in `screens: [...]` (drives the S drawer, presenter list and the Blueprint "All sources"); every slide's `sourceIds` must match (the store test checks both directions). Keep the on-slide `SrcTag` in sync too.
- Theme: paper = every non-separator slide whose act starts with "Act " (computed in `src/deck/theme.ts`); everything else is navy.
- Id-based hooks to update when renumbering: `POLL_SCREEN` in `src/lib/poll.ts` (`s2-challenge` → `S2`), `PRINT_CHOICE` in `src/routes/print.tsx` (currently empty). Timer boundaries are derived in `screens.ts`: `CLOSE_INDEX` = first slide whose act is "Closing" (talk = 1..CLOSE_INDEX − 1), `QA_INDEX` = the last slide (holds for Q&A).
- `slideLabel(i)` in `screens.ts` ("N / 51 · title") is the one label used by the control bar, presenter window, `document.title` and the `/present/$n` head.

## Behaviour
- No click-steps: each slide auto-plays its build; → always goes to the next slide (also mid-build); ← shows the previous slide complete (no replay); R replays.
- Build speed: elements enter in 200 ms, staggered 60 ms (timelines like `[60, 120, 180…]`); every normal build completes within 0.8 s. Counters and morphs (75% counter, reach circles, effort bar, ladder arcs) 600 ms; typed text ≤ 1 s; cold open ≤ 3 s (terminal lines 0.12 s apart). Ambient motion (lobby arcs) is exempt.
- Stop separators (4, 14, 20, 24, 32, 39, 46) are real navy slides that wait for → (no timed overlay): "STOP 0n" eyebrow, big title, muted question, act-colour line, giant stop numeral, quiet ArcMotif, and the 7-stop roadmap along the bottom.
- Optional keys only: 1–4 (chat votes on the slide-2 poll), 1–6 (career stage on 37 and 48), T (effort bar 2022/2026 on 33), Z (competency zoom on 42), S (sources), O (overview — separators shown as stop headers), G+number, N (presenter), B (blackout, navy), F, D (download PDF).
- One source of truth for the current slide; control bar "N / total · title", page title, `/present/N`, progress bar and presenter window always agree.
- Presenter timer: talk total 41:30 counts slides 1–49; separate "Close 2:00" for slides 50–51. The final slide holds: its countdown stops at 0 (no red), then a "Q&A 10:00" card counts down `QA_SEC` (stops at 0).

## PDF
- `/print` (noindex) renders every slide's final/print state at 1920×1080 per page, then /blueprint pages, sets `window.__PRINT_READY = true`.
- Generate: see README "Generate the PDF" (Playwright, `page.pdf({width:'1920px',height:'1080px',printBackground:true,tagged:true,outline:true})`). Playwright is a dev dependency (`bunx playwright install chromium` once). Locally: start the dev server, then `node scripts/export-pdf.mjs http://localhost:8080 AI-Era-Software-Engineering_Hany-Saad_BrainsMingle-2026.pdf`. Current output: 80 pages (52 slides + Resources title + 27 Blueprint pages).
- Lovable-hosted assets (`/__l5e/assets-v1/…`: monogram, QR images) 404 on the local dev server; `export-pdf.mjs` fetches them from the published site when the base URL isn't the live site. These 404s in local dev are expected.
- `*.pdf` is git-ignored except the current versioned file in `public/downloads/`; the unversioned PDF stays in the repo root locally.
- Every Download PDF button goes through the server-side deck gate, then downloads the release-bundled file as PDF_FILENAME. Re-generate, replace the versioned asset and update `PDF_ASSET_PATH` after any slide change.
- Print gotchas: large `rounded-full` divs print with a flattened bottom in Chromium's PDF output — draw big circles as SVG (as on slide 30 and the agenda rings on slide 3). When checking PDF pages with pdf.js, navy pages show a pink glow: that's a pdf.js rendering artifact, Chrome's viewer shows the correct navy glow.
